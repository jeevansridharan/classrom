# 📚 Classroom Doubt Exchange

A mobile-first academic Q&A platform — students anonymously post doubts and get answers from classmates. Built with **Flutter** + **Firebase**.

## 🚀 Setup Guide

### Step 1 — Install Flutter

```powershell
# Download from https://docs.flutter.dev/get-started/install/windows
# Then add to PATH and verify:
flutter doctor
```

### Step 2 — Create Firebase Project

1. Go to [console.firebase.google.com](https://console.firebase.google.com)
2. Create a new project
3. Enable:
   - **Authentication** → Email/Password
   - **Firestore Database** → Start in production mode
   - **Storage** → Start in production mode
   - **Functions** (requires Blaze plan)

### Step 3 — Configure Firebase in Flutter

```powershell
# Install FlutterFire CLI
dart pub global activate flutterfire_cli

# Inside the project directory:
cd classroom_doubt_exchange
flutterfire configure
```

This generates `lib/firebase_options.dart` — **replaces the placeholder**.

Also place `google-services.json` (from Firebase Console → Android app) at:
```
android/app/google-services.json
```

### Step 4 — Install Flutter Dependencies

```powershell
flutter pub get
```

### Step 5 — Deploy Firebase Rules & Indexes

```powershell
npm install -g firebase-tools
firebase login
firebase deploy --only firestore:rules,firestore:indexes
```

### Step 6 — Deploy Cloud Functions

```powershell
cd functions
npm install
cd ..
firebase deploy --only functions
```

### Step 7 — Run the App

```powershell
flutter run
```

## 🔒 Anonymity Model

- `authorUid` is **stored in Firestore** for moderation purposes (admins can query it via Firebase Console or Admin SDK).
- The `QuestionModel` and `AnswerModel` Dart classes **do not include `authorUid`** — it is never deserialized into client memory.
- The **author's pseudonym/handle** is stored separately and shown in the UI.
- Firestore Security Rules prevent direct modification of `reputationPoints` from the client — only Cloud Functions (running as admin) can update them on vote events.

## 🏆 Reputation System

| Action | Points |
|---|---|
| Question upvoted | +10 |
| Answer upvoted | +10 |
| Answer accepted | +25 |
| Casting an upvote | +5 |
| Downvote received | −2 |
| Un-accepting an answer | −25 |

**Tiers:** Newcomer → Learner (10) → Contributor (50) → Advanced (200) → Expert (500)

## 🧠 Duplicate Detection

When posting a question, a TF-IDF cosine similarity check runs against the 100 most recent questions. If similarity ≥ 0.35, the user sees a warning with links to similar questions. They can still post if their question is different.

The same algorithm runs in `functions/index.js` as a callable Cloud Function (`checkDuplicate`) for server-side validation.
